# How Raycast Reached a $100M+ Valuation (As a Small Startup)

## Summary

Tim Gabe breaks down four design decisions behind the growth of Raycast, a keyboard launcher for Mac. First, it embedded into the tools users already use, so integrations doubled as distribution. Second, its opinionated, keyboard-first UX trained new habits. Third, its search bar, extensions, store and API form a loop that adds value with use. Fourth, it over-delivered for one user: Mac developers who live on the keyboard. Tim argues that distribution is often a design problem in disguise.

## Key facts

- Raycast has hundreds of thousands of users and millions in funding. It has fewer than 40 people and a valuation over $100M (2025-05). [0:00](https://www.youtube.com/watch?v=eWGNjTLK84c&t=0s)
- At launch it already integrated with GitHub, Jira and Slack. Users opened assigned GitHub issues or updated Jira tickets without a browser. [0:32](https://www.youtube.com/watch?v=eWGNjTLK84c&t=32s)
- In the early days Raycast had no formal onboarding. Now it has a lightweight onboarding flow. [3:43](https://www.youtube.com/watch?v=eWGNjTLK84c&t=223s)
- Users built their own extensions from the start, but there was no full marketplace at launch. [4:46](https://www.youtube.com/watch?v=eWGNjTLK84c&t=286s)
- Its target user is the Mac-based developer who lives on the keyboard. [8:42](https://www.youtube.com/watch?v=eWGNjTLK84c&t=522s)
- Alfred was already popular in the same niche, with many features and options. [9:50](https://www.youtube.com/watch?v=eWGNjTLK84c&t=590s)

## Tactics

- **Embed in existing workflows.** Raycast did not pull users away from their tools. Its integrations do real work, not just show a logo. [0:32](https://www.youtube.com/watch?v=eWGNjTLK84c&t=32s)
- **Integrations are distribution.** A GitHub or Slack extension shows Raycast's value inside a tool the whole team uses. That creates pull with no referral tricks. [1:06](https://www.youtube.com/watch?v=eWGNjTLK84c&t=66s)
- **Ask where users already work.** A Chrome extension, a Slack command or a Notion embed can all put the product into a habit. [1:06](https://www.youtube.com/watch?v=eWGNjTLK84c&t=66s), [2:01](https://www.youtube.com/watch?v=eWGNjTLK84c&t=121s)
- **Be opinionated.** The keyboard is the main input, not a power feature. Heavy mouse use feels slow on purpose, to train a faster rhythm. [3:01](https://www.youtube.com/watch?v=eWGNjTLK84c&t=181s), [3:43](https://www.youtube.com/watch?v=eWGNjTLK84c&t=223s)
- **Zero clutter, progressive disclosure.** The interface stays minimal, and power shows up as the user goes deeper. The product teaches itself through use. [3:43](https://www.youtube.com/watch?v=eWGNjTLK84c&t=223s)
- **Strong constraints build habits.** The model is rigid: open, type, act. Users cannot change the layout. Sharp opinions turn some people away but create the strongest believers. [4:56](https://www.youtube.com/watch?v=eWGNjTLK84c&t=296s)
- **Design loops, not features.** Each extension adds reach to the search bar, such as Google Drive, Spotify or Notion. The store gives reasons to explore, and the API lets developers grow the store. [6:14](https://www.youtube.com/watch?v=eWGNjTLK84c&t=374s), [7:14](https://www.youtube.com/watch?v=eWGNjTLK84c&t=434s)
- **Onboarding never ends.** Ongoing surprise keeps activating users, as they find new things the app does. [7:14](https://www.youtube.com/watch?v=eWGNjTLK84c&t=434s)
- **Test each feature.** Ask: does it unlock something already in the product, or does it sit alone? Only the first kind compounds. [8:12](https://www.youtube.com/watch?v=eWGNjTLK84c&t=492s)
- **One filter for every decision.** Each feature must add speed, cut cognitive load or fit keyboard workflows. Other features stay out. [9:32](https://www.youtube.com/watch?v=eWGNjTLK84c&t=572s)
- **Compete on clarity, not features.** Against Alfred, Raycast chose a cleaner UI, better defaults and a large central search bar. [9:50](https://www.youtube.com/watch?v=eWGNjTLK84c&t=590s)
